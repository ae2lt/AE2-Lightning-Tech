# 猪咪水晶催化器验证

猪咪水晶催化器使用 64 个可重复使用的催化剂，每 100 个有效游戏刻产出 1 个水晶，即每分钟 12 个，完成时消耗 1000 mB 水。独立放置即可运行，不接受 FE，不使用坍缩矩阵，也不切换粉碎模式。

两种机器共用原有加工配方。配方的能耗、闪电与基础输入输出保持原值；猪咪版在机器执行层忽略能耗并应用上述固定规则。没有 `pigmee_*` 加工配方或配方变体字段。旧存档中的 `pigmee_*` 加工 ID 会迁移到对应原配方，保留进度和产物种类；旧版进行中快照也按每轮 1 个结算，已经进入输出槽的物品不受影响。

## 外观与界面

保留普通水晶催化器的 TedXenon 主体结构，猪咪外壳继续复用本模组 `pigmee_pattern_provider_side`。仅将顶面替换为用户选定的粉白方形图案 `textures/block/pigmee_crystal_catalyzer_top.png`（32×32），移除原水晶物品图标；顶盖保持平面，没有凹槽。机器中央沿用普通催化器的旋转催化剂物品渲染。

顶盖来源：内置 ImageGen 编辑普通催化器图集的配色草稿，提示要求“仅将紫黑色换成猪咪系列的浅珊瑚粉、灰玫瑰色与奶白色，保留方形图案，不添加水晶图标、凹槽或新装饰”。生成图未完整保留图集布局，因此没有整体使用；用户随后明确选定其中的顶盖方形图案，并要求其余外观保留现状。按用户同意的程序处理方式，从所给 235×245 截图裁取 `(23, 25)` 起的 200×205 图案区域，以最近邻采样导出 32×32 PNG，排除棋盘格边缘。模型仅替换顶面贴图，不修改其他面。

猪咪界面隐藏绑定频率、模式切换、坍缩矩阵和 FE 能量条，状态提示只显示运行状态及进度；仍保留自动输出设置。

## 自动化回归

```sh
./gradlew -I scripts/pigmee-catalyzer-test.init.gradle runGameTestServer --no-configuration-cache
./gradlew test build --no-configuration-cache
```

六项 GameTest 使用真实方块、能力接口与 AE 网格调度，不直接调用机器 tick：

- 六面物品/流体能力与 AE 节点能力存在，FE 能力不存在；模拟插入不改变库存，拒绝矩阵，两种机器选中同一配方，原配方的能耗、闪电和数量不变且没有猪咪副本。
- 无外部网络和电源连续加工两轮，每轮恰好 100 个有效 tick；催化剂保留，完成时才扣水。
- 63 个催化剂或 999 mB 水均不推进加工，补足后可恢复。
- 输出槽满时暂停，导出 1 个物品腾出最后一个空位后恢复，准确填满该空位且不丢物。
- 加工中 NBT 保存恢复，旧正能耗/零能耗的 `pigmee_*` 快照 ID 迁移，旧版 16 个产物的快照按新规则结算 1 个，拆除掉落保留催化剂与产物。
- 普通催化器仍需 FE/闪电，不能凭空加工。

## 真实客户端

```sh
./gradlew -I scripts/pigmee-catalyzer-test.init.gradle runClient --no-configuration-cache
# 第一次启动时，在该独立游戏目录创建名为 PigmeeCatalyzerTest 的测试世界。
# 后续可直接打开该世界：
./gradlew -I scripts/pigmee-catalyzer-test.init.gradle -PpigmeeQuickPlay runClient --no-configuration-cache
```

游戏目录在 `build/pigmee-catalyzer-client`，GameTest 目录在 `build/pigmee-catalyzer-gametest`。此脚本启用的客户端探针会清理测试玩家背包并在 (0, 100, 0) 附近建立比较场景，仅供上述独立世界使用。调试类位于 `src/jdb`，不进入发布 JAR。

客户端探针通过真实菜单网络包倒入一桶水，验证空桶返回、模式锁定、无 FE 进度同步、产物/水量/催化剂数量，再打开实时 EMI 原配方，确认仍声明 100000 FE、1 个高压闪电、1 个催化剂及 1 个基础产物，且没有零能耗猪咪副本。随后切换观察者视角，记录无 HUD 的顶视图和斜视图，并恢复生存模式。结果写到游戏目录下 `pigmee-catalyzer-client-probe.txt`，原始游戏截图位于其 `screenshots` 目录。
