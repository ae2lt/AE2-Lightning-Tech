# JEI 无线取料

## 范围与设置

天枢合成终端和天枢样板终端的「天枢设置」共用客户端布尔配置 `tianshuTerminal.jeiWirelessSupply`，默认关闭。开启后，只扩展 JEI 已选中的配方填充处理器；没有处理器、处理器拒绝当前配方、玩家背包界面和 ME 存储终端不启用此逻辑。不会注册新的机器处理器。

从饰品栏、背包或副手找到可连接的无线天枢终端。独立无线合成终端、独立无线样板终端和通用无线终端中的天枢模块均可作为来源；失联终端不会遮住后面的可用终端。每次操作只使用一个网络，沿用无线终端的连接、范围、升级卡和耗电规则。非物品材料仍由原处理器负责。

## 填充流程

1. 原处理器先执行只读预览。关闭开关或已有材料足够时走原调用；Shift 可以继续请求补料。
2. 客户端只查询配方输入中出现的物品类型；服务端返回 ME 网络实际存在、允许取出的组件精确物品及数量，暂不取料。
3. 在背包副本中模拟补料并调用原处理器预览，结束后恢复所有原堆叠。优先复用已有材料、选择库存充足的替代物，再用原处理器验证并缩减到实际缺额。Shift 扩大物品数量，原处理器决定最终的批量填充结果。
4. 点击后，服务端核对菜单对象、一次性请求、终端连接、网络身份、真实库存、电量与背包空间，再把真实取出的物品放入背包。
5. 背包同步先于确认包到达客户端。客户端只在原菜单、原配方界面仍有效时调用原 JEI 处理器完成填充。其他 Mixin 包装的原调用链也保留。

背包需要能暂存缺少的材料。背包已满时不会先消耗机器槽中的物品来腾地方。关闭界面、切换菜单或原处理器最终拒绝填充时，已成功取出的物品留在背包。新配置只控制 JEI 填充入口；EMI 自己的填充入口沿用其原行为。

## 服务端边界

查询和取料每包最多 256 项，单项最多 2304 个，实际一次背包插入总量最多 2304 个。服务端每位玩家最多保存 32 个临时报价，100 tick 后过期；报价绑定菜单对象、终端位置和网络身份，执行一次即移除，退出登录或服务器停止时清理。

客户端不能创建物品或组件：取料必须在报价范围内，且再次从真实 ME 存储中取出。库存不足、无空间、无电或连接变化会拒绝。若存储回调导致部分取出，提交前失败时将暂存物品退回原网络，退不回的部分交还玩家。背包提交仅修改插入计划涉及的槽，不会把无线终端耗掉的电量恢复为旧快照。

## 验证

- `./gradlew runJeiSupplyGameTestServer`：真实 ME 网络、原生 JEI 工作台服务端填充、电量、重复请求、伪造组件、背包空间、断电、失联、菜单替换、库存竞争、饰品栏、两种独立终端、通用无线终端模块。
- `./gradlew runJeiSupplyGameTestServer -Pae2ltDisableWtlibDevRuntime=true`：仅嵌入的无线终端 API 时仍可取料。
- `./gradlew runJeiSupplyClient -Pae2ltDisableEmiDevRuntime=true`：在 `run-jei-supply-client/saves/JeiSupplyQA` 的独立测试存档中，通过真实 JEI 调用与双向网络包验证关闭开关、普通点击、Shift、工作台、熔炉、铁砧、组件保留和有限背包空间；最后打开设置页供截图检查。该运行配置与探针仅用于开发，不进入发布 JAR，调试端口只监听本机。
