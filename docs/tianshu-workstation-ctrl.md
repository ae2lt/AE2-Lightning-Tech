# 天枢工作台 Ctrl 补料

天枢的合成台、锻造台、切石机和铁砧均可从 JEI / EMI 转移配方，并用 Ctrl 请求网络中可自动合成的缺料。有线与无线终端共用同一服务端逻辑。元件工作台不参与配方补料。

普通点击只转移现有物品。Ctrl 点击先使用工作槽、网络库存和背包中的实际材料，再对仍然缺少且存在样板的物品打开 AE2 原生合成确认。多个相同物品的缺额合并计数；例如铁砧需要四个铁锭、已有一个时只请求三个。确认并完成任务后，再次转移即可使用产出的材料。

服务端从配方 ID 解析实际锻造 / 切石配方，按当前库存、视图过滤和锁定背包槽重新检查。铁砧请求只携带输入模板；真实输入保留组件，输出、修理消耗和费用均由原生菜单及整合包回调决定。修理示例中的耐久度只用于匹配实际受损工具，不会用新造的完整工具代替修理目标。铁砧在服务端同步输入物品名称，避免配方界面遮住名称编辑框时误删名称。

## 发布方式

本次修复包含公共菜单和新增客户端动作，客户端与服务端必须一起更新。提供的 `workstationfix.4` JAR 基于已部署的 `2.1.0-beta.5-tianshu.2` 制作，包含此前 `clientfix.1` 的图标与 JEI 提示修复、`workstationfix.1` 的 Ctrl 补料修复、`workstationfix.2` 的元件工作台会话修复、`workstationfix.3` 的锻造台、铁砧、切石机输入与选择状态接续，以及工作台取出结果的音效；无需同时安装多份 AE2LT。

`scripts/package-tianshu-workstation-fix.py` 校验部署基包的 SHA-256，仅替换明确列出的类与模组版本，其余条目逐字节检查不变。测试探针不会打入正式 JAR。服务端应完整停止、替换 JAR 后重新启动，不能用 `/reload` 更新。

## 回归方法

- 用整合包副本运行 NeoForge 21.1.248、AE2 19.2.17、AE2WTLib 19.5.1、JEI 19.51.0.418；另一次冷启动加入 EMI 1.1.24。
- 建立真实网络，包含合成 CPU、样板供应器和分子装配室。探针调用实际 JEI / EMI 注册处理器及填充路径；调试器仅在相应转移调用中提供 Ctrl 状态，不替代材料提取、菜单包、计划计算或任务执行。
- 锻造使用 ATM 剑原配方，自动合成所缺 ATM 锭；切石使用石英砖原配方，自动合成石英块；铁砧使用受损且带名称 / 附魔的铁镐，自动合成铁锭。四锭需求用配方查看器公开工厂创建显示示例，修理与产出仍走真实铁砧。
- 校验合成确认菜单的请求数量、任务完成后的转移和结果取出。铁砧按整合包 Apothic Enchanting 的实际经验点规则校验费用，不能误以为显示等级未减少就没有收费。
- 回归原有 3×3 合成台的四木板补料，以及没有库存且没有样板时的缺料拒绝。

探针位于 `src/jdb/java/dev/infinity/terminalprobe/`。默认可用 `-I scripts/tianshu-transfer-test.init.gradle compileJdbJava` 编译 JEI 探针；要编译 EMI 探针，同时提供 `-PtianshuEmiProbeJar=/绝对路径/emi-neoforge-1.1.24+1.21.1.jar`。只在隔离测试存档中加载探针，它会清理角色背包并搭建测试网络。

## 元件工作台切换

原先元件属于当前菜单的临时输入，`removed()` 会立即将它返还背包。万能终端切换类型、打开合成确认都需要替换菜单，也会执行此回调；背包满时元件因此掉落。

现在旧菜单把元件及复制模式、过滤配置移交给该玩家的临时会话。同一维度、同一终端位置的 AE2 菜单可接续此会话；无线终端还核对原来的物品实例，防止另一台终端误接。返回天枢菜单时恢复元件和配置，升级卡、存储内容等仍保存在元件原有组件中。会话不与其他玩家共享。

普通工作页继续共用一个菜单。服务器在菜单替换结束后的 tick 核实是否真正离开：关闭界面、打开其他位置的容器、死亡或退出服务器时，按原规则返还元件；背包满时仅此时掉落一次。退出与服务器停止事件也会处理尚未接续的会话。

隔离探针的 `cell:setup` 使用带名称、模糊卡、两行过滤配置及 37 个钻石存储内容的元件（最终内容保留回归）；`cell:full` 填满背包，`cell:held` / `cell:returned` 检查背包与地面的元件总数，`cell:assert` 比较元件全部组件。`clickpage:*` 经实际界面鼠标点击，`wut:*` 经原生终端选择包；`cell:confirm` / `cell:main` 经过原生合成子菜单及返回流程。`cell:copyempty` / `cell:assertcopy` 检查取出元件后保留的复制配置。

## 锻造台、铁砧和切石机切换

这三个工作台的六个真实输入槽也使用上述玩家会话接续。铁砧保存当前编辑名称，切石机按配方 ID 恢复选择；输出槽和经验费用由原生工作台根据输入重新计算，不保存或返还预览结果。真正关闭时只返还尚未消耗的输入。

铁砧名称由服务端同步，重新打开编辑框不会把已编辑的名称覆盖成原物品名称。换入另一件物品时重新初始化名称；用户正在输入时不以迟到的同步消息覆盖输入。

`work:setup` 同时设置三个工作台的六个带唯一名称的输入、铁砧改名和切石配方选择；`work:assert` 比较所有输入、三个结果及铁砧费用。`work:held` / `work:returned` 校验背包和地面上的输入总数，`workview` 检查真实客户端的改名框。测试结果和具体运行限制随构建保存在 `evidence/validation.json`。

## 工作台取出音效

虚拟工作台的原版计算引擎使用 `ContainerLevelAccess.NULL`，原先连同世界交互一起跳过了原版音效回调。现在由终端在实际成功取出后从服务端播放对应的锻造、铁砧或切石取出音效，使用原版的方块音量分类、音量和音调范围，声音位于操作者处，有线和无线终端共用此逻辑。

每次操作只播放一次，整组、Shift 和批量制作不会按产出数量叠加声音。未取出结果、目标没有空间、经验不足，以及只切换工作页或恢复输入时均不播放。不会为恢复音效启用原版的方块损坏或移除逻辑。

隔离探针监听 `PlaySoundSourceEvent`，核对客户端已创建音频通道的声音 ID 和次数。`sound:reset` 清空计数，`sound:take:工作页:操作[:full|xp]` 验证成功取出或拒绝取出，`sound:assert:工作页:次数` 核对实际音频来源。
